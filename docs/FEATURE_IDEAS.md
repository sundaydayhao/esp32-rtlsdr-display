# ESP32-S31 RTL-SDR 功能规划

更新日期：2026-09-08。本文根据当前仓库代码提出后续方案；标为“建议”的功能尚未实现。难度是相对于现有工程的估计，不是硬件性能保证。

最值得先做的是 **自动搜台与收藏 → 瀑布图分析工具 → ADS-B 雷达视图 → RDS 台名显示**。这条路线能够逐步改善日常使用体验，并充分利用现有屏幕、触摸和音频链路。若更偏向无线协议研究，可优先做 **IQ 回放与 OOK 脉冲分析**。

## 1. 当前已有的基础

旧 README 中“其他页面仅为占位”的描述已落后于代码。以下是源码中已有的实现范围，不代表此次已完成上板验收。

| 页面/模块 | 已有实现 | 适合继续扩展的部分 |
| --- | --- | --- |
| Waterfall | FFT、滚动瀑布图、频谱标记、触摸调谐；默认 512 点 FFT、288 kS/s | 峰值保持、冻结、测量、截图 |
| FM Receiver | WFM/NFM 解调、单声道 PCM、音频波形、ES8389 扬声器输出；离开 FM 页停音 | 搜台、收藏、静噪、RDS、立体声 |
| ADS-B | 1090 MHz、2 MS/s 接收路径；报文解析、呼号/高度/速度/航向及 CPR 位置解码；接收器最多维护 24 架飞机 | 雷达视图、轨迹、接收统计 |
| Scanner | 默认扫描 88–108 MHz，分段调谐并拼接频谱；每跳预留 160 ms 稳定时间 | 可编辑扫描范围、强信号停留、占用统计 |
| Sensors | 默认 433.92 MHz、250 kS/s；OOK/ASK 脉冲分帧、宽度判决、原始数据与哈希 ID | 具体设备协议、校验、温湿度等物理量 |
| IQ Record | 原始交错 8-bit I/Q 写入 SPIFFS，单次最多 512 KiB | 文件管理、导出、回放、触发录制 |

相关入口为 `main/app_main.c`、`main/display.c`、`main/adsb.c`、`main/dsp.c`、`main/fm_receiver.c`、`main/rtlsdr.c`。特别注意：Sensors 当前显示的哈希 ID 不是已经确认的设备身份，原始脉冲判决也不是完整传感器协议解码。

## 2. 建议功能总览

P1 表示优先实现，P2 表示在基础体验稳定后增加，P3 表示适合单独验证可行性的进阶方向。

| 优先级 | 功能 | 能带来的体验 | 难度 | 额外条件 |
| --- | --- | --- | --- | --- |
| P1 | 自动搜台、收藏与设置记忆 | 一键找台、保存台名，重启后恢复频率和音量 | 中 | 无新增硬件 |
| P1 | 频谱冻结、峰值保持、双标记 | 抓住短促信号，测量两个峰之间的频差 | 低～中 | 无新增硬件 |
| P1 | ADS-B 雷达与轨迹 | 小屏显示附近飞机的位置、方向和历史航迹 | 中 | 本机经纬度；手动设置即可 |
| P1 | 接收质量与调谐面板 | 看清增益、丢样和处理负载，定位卡顿或弱信号问题 | 中 | 实测调谐器支持情况 |
| P2 | RDS 台名与广播文本 | FM 页显示台名和滚动文字 | 高 | 当地电台发送 RDS/RBDS |
| P2 | 智能扫描与频段占用热图 | 自动寻找活跃频点，记录何时出现信号 | 中～高 | 需要较长时间观测 |
| P2 | OOK 脉冲示波器与传感器协议 | 看遥控器波形，显示已支持设备的温湿度等数据 | 中～高 | 已知协议设备、可复现的录制样本 |
| P2 | IQ 文件导出、回放与触发录制 | 把偶发信号存下来，离线反复分析 | 中～高 | 长录制需额外存储或网络 |
| P2 | 手机网页遥控与实时预览 | 手机调频、查看频谱、下载录制文件 | 中 | Wi-Fi 网络或设备热点 |
| P3 | FM 立体声与音频录制 | 收听真正的左右声道，保存节目片段 | 高 | 立体声监听设备；确认实际音频连线 |
| P3 | APRS 地图/消息接收 | 显示附近业余无线电台的位置和公开消息 | 高 | 本地有可接收的 APRS 信号 |
| P3 | 信号“图鉴”与教学模式 | 用录制样本演示 FM、OOK、FSK 的频谱特征 | 中 | 先完成回放和样本管理 |

## 3. 优先功能怎样落地

### 3.1 自动搜台、收藏与设置记忆

**效果：** FM 页增加“上一台 / 搜台 / 下一台”和收藏入口，收藏条目包含名称、频率、模式。重启后恢复各页面自己的频率和音量。

**最小实现：** 在现有 Scanner 调谐逻辑上增加专门的 FM 搜台状态机，先支持一个可配置的广播频段和步进。使用局部噪声底、持续时间和信号强度共同筛选候选台，避免把单个毛刺作为电台。进入候选频道后停留确认；切换页面时取消搜台。静噪开关增加迟滞和短淡入淡出，减轻临界信号时反复开关音频的问题。

**代码入口：** 从 `app_main.c` 提取 `scanner.c`；为 `rtlsdr.c` 增加“调谐完成”反馈；在 `display.c` 增加小型收藏列表；用 `settings.c` 和 NVS 保存设置。写 NVS 前做延迟合并，避免每次拖动都写 Flash。

**验收：** 空频点不持续输出底噪；搜台能跳过弱噪声峰；快速返回主页立即停音；重启后恢复设置；修改 FM 频率不覆盖 Waterfall 的保存值。

### 3.2 瀑布图变成便携信号观察工具

**效果：** 增加暂停/继续、峰值保持、双标记频差、可调显示范围和截图。触摸峰值时显示更细的频率读数。

**最小实现：** 峰值保持和双标记先只保存少量频谱数组；冻结显示时允许采集继续。将“图像放大”和“降低采样率以提高频率分辨率”明确区分。默认 288 kS/s、512 点 FFT 的 bin 间距是 `288000 / 512 = 562.5 Hz`，仅放大图像不会提高真实分辨率。

**代码入口：** `dsp.c` 保留映射成 0–255 颜色值之前的幅度数据，`display.c` 负责游标、暂停与图层。显示相对幅度或经过明确定义的 dBFS；绝对 dBm 读数需另做输入功率校准。

**验收：** 固定信号位置稳定；双标记频差与已知测试信号相符；调整色阶不改变测量结果；退出冻结后不会一次补画大量历史帧。

### 3.3 ADS-B 雷达视图与接收统计

**效果：** 以接收机为中心显示距离环、飞机方向与短轨迹，点选后查看呼号、高度、速度和最后接收时间。增加每秒有效报文、最远接收距离等统计。

**最小实现：** 用用户设置的接收机经纬度换算相对距离和方位，先画不依赖地图瓦片的二维雷达。没有位置的飞机继续保留在列表中；过期轨迹淡出；轨迹点数固定上限，避免长期运行耗尽内存。

**代码入口：** 复用 `adsb.c` 已解析的经纬度与时间戳，在 `display.c` 增加雷达绘制和飞机详情。不要把“新增 ADS-B 解码器”当成起点。后续可参考 [readsb 项目](https://github.com/wiedehopf/readsb) 的输出组织方式设计导出接口，兼容性需单独验证。

**验收：** 用已知位置样本验证方位、距离和超时处理；2 MS/s 下统计 IQ 丢样及有效报文率；切入 FM 后释放 ADS-B 对接收机的占用。显示的是被动接收的飞机位置可视化。

### 3.4 接收质量与调谐面板

**效果：** 展示实际中心频率/采样率、调谐器型号、增益模式、USB 数据率、IQ 队列丢弃数、解调耗时、LCD FPS、内部 RAM/PSRAM 剩余量。

**最小实现：** 先显示已有 `iq_ring_frames`、`iq_ring_drops` 和运行参数，新增计数时使用同步快照。之后支持运行时调节 tuner gain 和频偏校正；按调谐器能力启用控件，不支持的操作返回清楚的状态。

**代码入口：** `rtlsdr.h/.c` 增加状态快照和排队设置 API；`app_main.c` 汇总队列与耗时；`display.c` 使用低频刷新，避免监控本身拖慢接收。

**验收：** 显示“已应用”的值来自实际成功设置；调谐失败时不冒充成功；能够区分 USB 没数据、队列丢样和音频输出未就绪。

## 4. 第二阶段：让接收到的信号更有内容

### 4.1 FM RDS 台名与广播文本

**效果：** FM 页面显示台名、节目类型和广播文本；没有 RDS 的频道显示未锁定状态。

**实现方向：** 从 FM 鉴频后的复合基带分出 RDS 支路，完成载波/符号同步、分组校验和文本组装。当前音频低通会去掉 RDS 所需的高频部分，因此不能从最终 48 kHz PCM 接入。可参考 [gr-rds 的接收实现](https://github.com/bastibl/gr-rds)，在本工程中设计适合 MCU 的精简处理链。

**最小版本与验收：** 先实现锁定状态、PI、PS 台名，再加入 RadioText。使用已知 IQ 样本验证，CRC 不通过不更新文本；换台立即清空旧台文本；评估额外 CPU 负载和音频连续性。

### 4.2 智能扫描与频段占用热图

**效果：** 设置频率范围、步进、驻留时间和门限，发现活跃频点自动停留；用“频率 × 时间”热图观察一段时间里的活动。

**实现方向：** 在现有拼接扫描上增加调谐完成确认、旧样本丢弃、扫描频段配置、每段噪声底与占用统计。当前 160 ms 延时只是一种等待策略，未来应先确认硬件调谐成功，再开始稳定等待和测量。

**最小版本与验收：** 先做一个频段的强信号列表及点击调谐；再做热图和 CSV 导出。拼接频谱是依次测量，整段并非同一时刻采集，UI 应给出完整扫描周期。相邻段适当重叠，并验证边缘频点不会遗漏。

### 4.3 OOK 脉冲示波器与传感器数据

**效果：** 按下遥控器时看到脉冲序列、脉宽直方图和重复帧；识别受支持的温湿度计等设备后，显示带单位的数据和历史曲线。

**实现方向：** 将 `app_main.c` 中的脉冲检测拆为 `sensor_receiver.c`，增加原始脉冲导出和可插拔协议解码。先挑手头一款设备，做同步头、位序、长度、校验和及重复帧过滤，再扩展协议。参考 [rtl_433](https://github.com/merbanan/rtl_433) 的脉冲分析与设备解码代码；移植具体代码时按其许可证处理。

**最小版本与验收：** 第一版只支持一种明确协议，并保留未知协议的原始帧视图。有效样本的物理量与设备屏幕一致；错误校验帧不产生温湿度数据；持续噪声不会不断生成新设备。

### 4.4 IQ 导出、回放与触发录制

**效果：** 提供录制开始/停止、文件列表、下载和回放；短促信号超过门限时自动保留触发前后的一小段数据。

**现有限制：** 当前单次上限 512 KiB。8-bit I 加 8-bit Q，每个复采样占 2 字节，因此在 288 kS/s 下只够约 **0.91 秒**，在 2 MS/s 下只够约 **0.13 秒**。现有 SPIFFS 存储分区为 `0xF0000`（960 KiB），不能直接作为长时间录音盘。

**实现方向：** 优先把现有短录制做成可靠的文件管理与导出；元数据记录数据类型、中心频率、采样率、时间和丢样，可采用 [SigMF 规范](https://sigmf.org/) 的数据文件加 JSON 元数据组织方式。回放通过统一 IQ 数据源接口送入现有 DSP/解码器，并按文件元数据设置解码参数。为存储建立独立任务和有界队列，避免 DSP 任务直接等待 Flash 写入。

**进阶条件与验收：** 长录制再评估 SD 卡接线或网络流；确认板卡引脚与 LCD/I2S 不冲突。记录队列满时明确提示丢样，文件写满能正常关闭，回放不占用实时调谐器。触发前缓冲用 PSRAM，但需先测可分配空间和持续写速率。

### 4.5 手机网页遥控与预览

**效果：** 手机浏览器查看频谱和接收状态、调频、选择收藏台、下载录制文件。

**实现方向：** 先实现 HTTP 状态/设置接口和低帧率频谱预览，再增加 WebSocket 推送。浏览器操作与 LCD 操作共用一条控制队列；连接断开不会阻塞 USB 或音频任务。网络端优先发送降采样频谱或已解码数据，原始 IQ 网络流另做吞吐测试。

**验收：** 两个控制入口的频率、页面和音量一致；慢客户端不会拉低音频连续性；本地操作优先响应；Wi-Fi 开启后重新测量 USB、内存和实时处理余量。网络能力依具体 IDF 6.1 与开发板组合实测后启用。

## 5. 适合单独探索的功能

| 方向 | 第一版范围 | 主要难点/依赖 |
| --- | --- | --- |
| FM 立体声 | 导频锁定指示、立体声解码、弱信号退回单声道 | 当前后端只是把单声道复制到左右声道；需要新增解码链并确认监听设备能分辨左右声道 |
| 音频录制 | 保存已有单声道 PCM 为 WAV | 48 kHz、16-bit 单声道约 96 kB/s，512 KiB 只够约 5.46 秒；长录制需要扩展存储 |
| APRS 接收 | 先从已知样本解码 AX.25/APRS 消息，再显示位置 | 需要 AFSK 解调、帧校验、本地频段设置和真实信号验证；可参考 [Dire Wolf 的接收实现](https://github.com/wb2osz/direwolf) |
| 信号图鉴 | 内置少量 FM/OOK/FSK 样本与注释，可切换时域/频域 | 依赖稳定回放；标签应来自已知样本，后续自动识别先显示候选和置信度 |
| 无线更新 | 网页显示固件版本并更新 | 目前分区只有一个 factory 应用，没有 OTA 双槽；需确认 Flash 实际容量并重新规划分区 |

## 6. 共用架构与实施顺序

**先统一接收机控制。** 只有一个物理 RTL-SDR 调谐器，FM、1090 MHz ADS-B、433 MHz 传感器和扫描不能同时各自接收不同中心频率。引入一个接收会话管理模块，统一拥有者、目标频率、采样率、调谐完成/失败事件与流重置。每次切换会话为 IQ 数据附带代次或清空旧队列，避免新页面处理上一页的旧频率样本。FM 扬声器仍只在 FM 页启用。

**再隔离耗时工作。** USB 回调仅入队；DSP/解码、LCD、存储、网络分别通过有界队列协作。现有 `app_main.c` 已承担扫描、传感器和录制逻辑，扩展时逐个提取模块更容易维护。LCD 保持精简控件，细节放在可打开的设置/详情面板。

**先量资源，再加负载。** 当前配置 Flash 为 2 MiB，factory 应用分区只有 1 MiB；硬件实际容量须确认后才能扩大。增加协议库、Wi-Fi 或 OTA 前记录固件大小、空闲内存和丢样率；先保证 288 kS/s 的 FM/瀑布图稳定，再以 ADS-B 的 2 MS/s 做压力验证。

建议按以下里程碑交付，每项完成后再进入下一项：

1. **接收基础：** 状态快照、调谐完成事件、页面会话切换、设置记忆。
2. **日常使用：** FM 搜台与收藏、静噪、峰值保持和双标记。
3. **可视化内容：** ADS-B 雷达与统计；有 RDS 电台时加入台名显示。
4. **研究工具：** IQ 导出/回放、OOK 脉冲分析及一个确定的传感器协议。
5. **扩展交互：** 网页遥控，再依据实测余量决定长录制、立体声或 APRS。

每个里程碑都应使用 `idf.py --preview build` 编译，并以已知 IQ 样本加真实硬件验证对应链路。本文列出的验收是未来功能的交付条件，不代表已经执行。
